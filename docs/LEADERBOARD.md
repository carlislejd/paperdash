# Leaderboards and PAPER ownership

PAPER ranking orders current ownership: unstaked wallet balance plus staked PAPER. The account directory's `paperTotal` was reconciled against both components of live wallet snapshots, including a fully staked wallet. Use the source's `paperTotal` sort with the selected statistics window, `all` by default or `24h`. Ownership and ranking remain current in both windows. Query parameters must be canonically sorted. The source's hidden `_leaderboardRank` is not the PAPER rank; rank is page offset plus row index.

The API exposes `metric: "paper"`, `window: "current"`, `statsWindow: "all" | "24h"`, and exact 18-decimal `paperTotalRaw` in rows. The dashboard and CLI default PAPER statistics to lifetime by explicitly requesting `GET /api/leaderboard?metric=paper&window=all`; use `window=24h` for rolling activity. An omitted API `window` preserves the old 24-hour contract so older clients remain correctly labeled during deployment. Other rankings support only `24h`; requesting `all` for them returns 400. PnL-ranked rows also include current PAPER ownership. `paperOwnership.trackedTotalRaw` is the same response's directory-wide tracked PAPER total, unchanged by an address filter; `pageTotalRaw` is an integer sum of returned holdings. `pageShareBps` is the page's fraction of that tracked total, rounded down to basis points, or null for a zero/incompatible denominator. This is not an independently reconciled global supply or positive-holder count. Account counts include zero balances. Filtered ranks describe the filtered set.

Lifetime PAPER rows use the source account's exact `realizedPnl` as `pnlRaw` and `totalVolume` as `volumeRaw` (18-decimal integer strings). `volumeUsd` and `assetsTraded` are null in this mode. `tradeCount` counts retained closed or liquidated position records, including records excluded from hold-time/leverage averages; it does not count execution events, opens or partially closed executions. Per-row `historyCoverage` reports the last successful trade-history check, backfill completion, projection backlog, excluded records and freshness independently of the source account snapshot. Positive retained counts remain usable with pending coverage. A checked empty history becomes zero only once its projection is caught up; an unknown or failed count stays null.

Release verification reconciled the all-window account fields against a saved live-wallet `lifetime` object for a holder with no observed 24-hour executions. Account `realizedPnl` exactly matched `lifetime.realizedPnlRaw`, and `totalVolume` exactly matched `lifetime.tradedNotionalRaw`, including every raw digit. This verifies the chosen lifetime mapping for that sample; it does not turn those fields into 24-hour values or establish completeness of the retained close ledger.

This reuses one cached source account page and one bounded, shared 20-second batch for its displayed wallets. Lifetime counts use precomputed position rollups plus indexed history-job and projection-queue probes; no raw history scan or per-wallet source requests are added. Lifetime mode does not query 24-hour activity. Successful shared PAPER page loaders retain and promote at most 25 displayed accounts through the existing history scheduler. Cache hits add no scheduling writes; promotion preserves saved cursors, retained records and retry deadlines. Existing source request limits and scheduler concurrency are unchanged.

The default rolling-24-hour PnL leaderboard keeps the source account ranking. Its current unrealized PnL comes from the same account snapshot and is distinct from the 24-hour PnL used for ordering. Trade counts, volume, and traded assets come from retained public trade observations within the last 24 hours; they include opens, closes, and liquidations and remain partial coverage.

Activity is queried in one batch for at most 25 displayed wallets and cached for 20 seconds through the existing shared-cache coordination. A cached page is reused only when its address set matches the requested accounts. No per-wallet upstream calls are added. Activity timestamps and stale flags are separate from the account valuation timestamp and stale flag.

Volume and trade-count rankings continue to use retained observations. These rankings expose observed assets but leave current uPnL and PAPER ownership unavailable because the activity query does not provide account valuations. Unknown values render as an em dash; zero activity and an empty observed asset set are shown only when the projection supports them. BTC and ETH badges describe assets traded during the window, not currently open positions.

The wallet/time/fingerprint index bounds asset lookups to the requested wallets and time window. PostgreSQL creates it concurrently in a separate owner migration session after the schema transaction. The migration verifies its definition and validity, preserves an already valid index, and repairs an interrupted matching build on retry. Runtime connections only check the catalog. The maintenance session has a bounded 120-second server statement timeout and 130-second client deadline; API and collector query deadlines are unchanged.
