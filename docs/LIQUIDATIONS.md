# Observed liquidation feed

The verified public Papertrade execution ticker identifies liquidations with `kind: 'liq'`. Wallet closed-position history separately uses `kind: 'Liquidated'`. This feed uses the retained public ticker/recent-API observations; it is not a reconstruction of all protocol liquidations. [Source contracts](../research/DATA_SOURCES_2026-10-09.md), [price and public-stream verification](ASSET_MARKET.md).

`GET /api/liquidations` returns 50 newest retained liquidation observations, a next cursor, cached rolling 1h/24h totals, freshness and collection coverage. Optional `instrument=0|1` selects BTC or ETH. Optional `cursor` requests the next older page. Totals cover the selected asset or all assets, not just the visible page. Counts include liquidations only; notional is approximate USD execution size, not lost margin or realized PnL. Direction is the liquidated trader's side. The original leverage and optional verified execution exit price are preserved.

The projection stores one membership per raw observation ID and a fingerprint of its economic fields. For indistinguishable events it counts `max(public-stream occurrences, recent-api occurrences)`: overlapping transport deliveries are not added together, but repeated identical executions in either transport are retained. This heuristic remains identity-ambiguous; it does not prove canonical execution identity. Price metadata is excluded from identity and can enrich an existing row without recounting. Feed IDs use `liq:<fingerprint>:<occurrence>` so a later overlapping source does not change the visible row's ID. The source observation remains in the original durable raw table.

Live projection runs inside the transaction that inserts each raw trade. Membership, counts, minute totals and visible rows commit together. Legacy raw observations are backfilled once with a persisted keyset checkpoint; each call is bounded in row count and checks a three-second work budget between projections. PG commits one observation and checkpoint per transaction. One in-flight database operation may finish beyond that budget, subject to the connection's statement timeout. The collector schedules backfill independently from current-view refresh. Live writes behind an already-completed backfill cursor still project immediately.

Rolling totals add full-minute aggregates to exact boundary observations, with inclusive `[now-window, now]` endpoints. Future-dated observations are excluded until their timestamp enters the window. The worker builds global/BTC/ETH snapshots every five seconds; first-page public reads use these saved snapshots. Older pages use a composite `(source_at,id)` index seek with `LIMIT 51` and return at most 50 rows. There is no full-history aggregate or directory crawl per viewer.

Cursors bind the instrument filter, last timestamp/ID and initial time ceiling. Newer head events cannot displace an older page. Backfill can still insert old observations around a cursor; pagination does not represent an immutable full-history snapshot. Refresh the head to see newly retained observations. An exhausted cursor does not promise the upstream archive is complete.

`coverage.partial` and `identityAmbiguous` remain true. `projectionBackfillComplete` only describes the local projection over retained raw rows. An unfinished backfill does not itself mean collection is stale; failed backfill/refresh loops, unavailable trade transports, or old collector/snapshot timestamps do. The frontend uses incoming liquidation notifications to schedule a bounded first-page refresh, preserving retained feed identity rather than appending unrelated raw observation IDs.
